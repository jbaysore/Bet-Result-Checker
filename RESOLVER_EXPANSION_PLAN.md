## Phase 0 — URGENT: quarter-line guard (stops silent wrong settlements today)

`_parse_spread_selection` happily parses `"Argentina -0.75"` and `_resolve_spread`
settles it binary WIN/LOSS — but quarter lines settle as two half-stakes (a −0.75 with a
1-goal win is a HALF WIN). Same exposure in `_resolve_total` for Asian quarter totals
(2.25/2.75), which the scanner's same-point soccer rows can produce.

- In `_resolve_spread` and `_resolve_total`: if `line % 0.5 != 0` (use Decimal or a
  0.25-epsilon check, not float modulo), raise
  `ValueError("quarter-point line -- settles as two half-stakes; manual until Phase 2")`.
  The poller already routes resolver ValueErrors to manual review — no poller change.
- Tests: −0.75 / +0.25 spreads and 2.25 / 2.75 totals raise; −0.5 / +7 / 2.5 do not.
- This guard is REMOVED by Phase 2, which replaces it with real half-win math.

## Phase 1 — Team totals (existing scores, one new parser branch)

Selection format (machine-generated by odds-tool `positionKelly.mjs`):
`"{TeamShort} Team Total {Over|Under} {line}"` (e.g. `"Braves Team Total Over 4.5"`),
logged as Bet Type `Total`. `market_key_infer.py` already recognizes the pattern —
reuse its regex sensibility, don't invent a second one.

- In the `BET_TYPE_TOTAL` branch of `resolve()`: try the team-total pattern FIRST
  (`^(.+?)\s+Team Total\s+(Over|Under)\s+([\d.]+)$`, case-insensitive); on match call a
  new `_resolve_team_total(team_part, direction, line, team1, team2, home_team,
  away_team, home_score, away_score)`:
  - Resolve which side via the existing `_resolve_team`/`_team_matches` helpers (they
    already handle short names like "Braves" vs "Atlanta Braves" for spreads — reuse,
    do not write new matching). No match → ValueError → manual.
  - Compare that team's OWN score to the line: over/under/push, integer lines push.
  - Quarter-line guard from Phase 0 applies here too until Phase 2.
- Parlay legs benefit automatically (`resolve_parlay` calls `resolve` per leg).
- Tests: both teams quoted at the same point (settle each side against ITS OWN score —
  the classic trap), short-name matching, push on exact, Over and Under, a parlay
  containing a team-total leg, and the malformed-selection fallthrough to plain totals
  parsing (a normal "Over 8.5" must still resolve as a game total).

## Phase 2 — Half-win settlement (`HALF WIN` / `HALF LOSS`)

### Resolver
- `config.py`: `RESULT_HALF_WIN = "HALF WIN"`, `RESULT_HALF_LOSS = "HALF LOSS"`.
- Quarter line L decomposes into two half-stakes at L−0.25 and L+0.25. Resolve each
  half with the existing binary logic and combine:
  (WIN, WIN)→WIN · (WIN, PUSH)→HALF WIN · (PUSH, LOSS)→HALF LOSS · (LOSS, LOSS)→LOSS.
  (WIN, LOSS) is arithmetically impossible for adjacent halves — assert it.
  Applies to quarter spreads AND quarter totals; Phase 0's guard comes out.
- `calculate_pl_and_payout`:
  - HALF WIN: profit = full-precision odds-profit on stake/2, rounded ONCE at the end
    per the book's existing rounding convention (PROPOSED — flag if a real settlement
    disagrees); payout = stake + profit; fee per the existing WIN fee rules.
  - HALF LOSS: P/L = −stake/2 − fee per the existing LOSS fee rules (PROPOSED: fee
    treated as on a loss; verify against one real settlement and adjust).
- **Parlays containing a HALF result → manual** (books' parlay half-win conventions
  vary; rare case; accuracy first). `combine_parlay_results` treats HALF WIN/HALF LOSS
  legs by raising → poller manual path.

## Phase 3 — Player props via box scores (MLB first) — the big one

### Source: `sources/mlb_statsapi.py`
Official MLB Stats API (statsapi.mlb.com, free, no key):
schedule-by-date → gamePk (+ official game status), boxscore → per-player batting/
pitching stats. This is the settlement-grade source; do NOT use TOA or ESPN for MLB
stats.

### Scope guard (accuracy first)
v1 parses ONLY machine-generated selections from the pick'em/promo tools:
`"{Player} {Over|Under} {line} {StatLabel}"`. Anything that doesn't match exactly →
manual, as today. Stat-label map (from the tools' MARKET_LABEL — keep in lockstep):
Hits, Total Bases, Home Runs, RBIs, Runs, Singles (hits−2B−3B−HR), Walks, H+R+RBI,
Stolen Bases → batting; Strikeouts, Outs, Hits Allowed, Earned Runs → pitching.
VERIFY each field name against a real boxscore payload before trusting it.

### The accuracy machinery (all RATIFIED policies land here)
- **Name matching:** normalize both sides (strip accents — "Acuña"→"Acuna" — case,
  punctuation, Jr/Sr/II suffixes); require EXACT normalized match, no fuzzy scoring.
  No match → manual.
- **DNP:** player entirely absent from the final boxscore → leg VOID. Player present
  but with zero qualifying appearance (batter with 0 plate appearances; pitcher with 0
  batters faced) → MANUAL (ambiguous). Present with real appearance and a 0 stat →
  a genuine 0, settles normally.
- **Final + re-verify (stateless — this repo deploys on Railway, no durable disk):**
  state lives IN the sheet row. First run that sees the game officially Final writes a
  staging marker into Notes: `props-observed: {leg:result,...} @ <iso>` — and does NOT
  settle. A later run ≥ 60 min after the marker re-fetches, compares: identical →
  settle and strip the marker; different → manual + notification with both snapshots.
  Suspended/called games (status not a clean Final) → manual.
- **Pick'em entries:** odds-tool's pick'em composer and DFS promo tool append
  `Pickem {mode} {n}-pick` to the bet's Notes at log time (odds-tool change; the
  /api/bets path already carries notes). Checker behavior for a Parlay whose Notes
  match: resolve every leg from box scores, then —
  - power/standard + ALL legs WIN → settle at the row's combined odds (that IS the
    top-tier multiplier);
  - power with any loss and no voids → LOSS (normal);
  - ANY void/reduced outcome, or mode = flex → write per-leg results + hit count into
    Notes and route to **manual-payout entry** (the Kalshi path —
    `MANUAL_PAYOUT_REQUIRED_BOOKS` machinery), because reduced/flex payouts come from
    the site's tables, which are app-truth.
  - Parlay rows with Prop legs and NO Pickem marker → manual (old rows predate the
    convention; don't guess).
- **SHADOW MODE gate (reliability):** ship behind `PROPS_SHADOW_MODE = True` — the
  resolver computes and writes its proposed result into Notes but does NOT settle;
  notifications still ring. Josh compares proposals against his manual settlements for
  ~a week of slates; flip to live only after he reports agreement. This is the phase's
  acceptance gate — do not skip it.
- Tests: fixture boxscore payloads (checked into tests/, from real API responses) for
  every stat label; accent/suffix matching; DNP-void vs ambiguous-manual; the
  observed-then-confirm two-pass; pick'em power settle / flex manual-payout routing;
  singles derivation (H−2B−3B−HR).

WNBA/NBA/NFL via ESPN box-score JSON are a later phase — same skeleton, new source
module + stat maps. Do not build speculatively.

## Traps checklist
1. **Fail toward manual, always.** Every new parse/match failure raises; the poller's
   existing ValueError → manual path is the safety net. Never default a branch to LOSS
   or WIN.
2. **Quarter detection must not use float modulo** (0.75 % 0.5 float noise) — Decimal
   or epsilon.
3. **Team totals: settle against the TEAM's score**, and both teams often share a line
   — the fixture must prove each side settles independently.
4. **Result-value enumeration audit** (Phase 2) spans BOTH repos in one change — a JS
   view that whitelists Result values will break or miscount silently.
5. **Railway = no durable disk** — re-verify state lives in the sheet row (Notes
   marker), never a local file.
6. **Pick'em reduced entries are NOT product-odds parlays** — a void leg changes the
   multiplier TABLE, not the odds product; that's why reduction routes to
   manual-payout. `combine_parlay_results`'s void-drop math must never touch a
   Pickem-marked row.
7. **Shadow mode is the Phase 3 gate** — live settlement only after Josh's observed
   agreement, and the flag stays as a permanent kill switch.
8. Per-leg odds in pick'em rows are blank/combined by convention — never parse leg
   odds from Pickem-marked rows.
